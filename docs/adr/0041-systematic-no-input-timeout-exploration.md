# 系统性探索无输入超时路径

IVR 输入节点在无输入时的超时路径（菜单重播 → 继续提醒 → 挂断）此前只在
Apple 4006668800 的 `1w1` 上偶然观察到，并靠事后脚本手工补录进树。项目决定
把无输入超时路径提升为输入节点的一等公民分支，由引擎系统性探索：

- **规则**：除隐私同意提示与人工节点外，每个输入节点都必须探索其无输入
  超时路径，一直观测到终态。终态总是挂断——无输入转人工是对坐席人力资源
  的浪费，规范的 IVR 设计不这样做；若观测到转人工，按异常记录。
- **建模**：沿用 `1w1-timeout` 先例，超时路径经合成的 `no-input` 边挂在
  所属输入节点下，该边不作为 DTMF 键重放。
- **探法（搭车 + 代表节点）**：分支探索电话到达菜单后先故意沉默至第一轮
  继续提醒，按任意键回到菜单，再继续原定分支——零额外成本捕捉"重播 +
  提醒①"证据；完整的超时周期观测每个菜单只挑一个代表节点做专用电话，
  因为超时行为是菜单级属性，同一菜单的所有分支共享同一套提醒话术。
- **专用探法（按键应答最终提醒）**：专用观测电话在重播期间保持沉默；
  听到**最终提醒**（"很抱歉，如果您还在线上，我听不见您的声音。若要
  继续，请按任意键。**否则，我将需要结束这通话**"）后按一个应答键
  （`any_key_value`），随后继续沉默直至对方挂断。全程一言不发会漏掉
  最终提醒之后的真实行为——应答键让 IVR 走完它设计的完整路径，观测到
  的挂断才是菜单的真实终态。最终提醒由实时决策引擎按措辞特征
  （"否则……结束……通话"）识别并发出 `final_any_key_prompt` 事件。
- **真实终态（2026-10-03 操作员实证修正）**：在最终提醒处按键后，IVR
  并不会立刻结束，而是继续重播约两轮（约 60 秒，疑似后台尝试恢复或
  转接），随后播报"**我们目前碰到一些技术上的问题。请稍后再来电。
  感谢您致电 Apple。**"再挂断。此前版本把更晚出现的"非常抱歉，仍然
  听不见任何声音"误判为最终提醒——在该行按键只会开启下一轮菜单重播
  循环，探针因而永远等不到技术问题宣告。引擎特征已相应改为识别
  "否则……结束……通话"，"仍然听不见"不再作为终态判据。
- **时长与录音上限**：两轮完整周期实测约 4 分钟（4006668800：子菜单起
  ~127 秒/轮）。专用电话时长上限 310 秒（`NO_INPUT_CALL_MAX_DURATION`），
  观测窗口 260 秒（`timeout_probe_max_s`），使单声道混缩后的录音仍低于
  腾讯文件 ASR 的 5 MB 上限（8 kHz 16-bit 单声道约 312 秒）。
- **隐私同意提示**收不到同意按键时直接挂断、无提醒循环，**人工节点**无
  超时语义且已探到者不再重复探索，两者均不适用本规则。

## Consequences

- 引擎需要新增"提醒语检测 → 按任意键 → 再沉默 → 等对方挂断"的通话内
  状态机扩展；`no-input` 成为发现层一等公民 plan token。
- 每个菜单约增加一通专用观测电话，计入发现窗口预算。
- 树上将出现更多 `no-input` 合成边与 `(timeout)` 标记节点，报告与前端
  需按特殊分支展示（已有先例）。
