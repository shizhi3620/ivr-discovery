# 实时大模型只做影子判断与双向否决

实时通话控制不把 DTMF 发送或菜单导航交给大模型。大模型与确定性规则并行消费同一份实时 ASR 文本，其输出只能用于审计、报告和双向否决。影子模型使用 `deepseek-chat`、`temperature=0` 和强制 JSON 输出，基于当前通话最近 60 秒或 2000 字符（先到者为准）的滚动 ASR 上下文做三分类，不接收菜单树或规则判断结果：`ivr_menu`、`automated_notice`、`human_or_unknown`；只有分类参与否决逻辑，`confidence` 和 `reason` 用于门槛与审计。目标键识别、静音窗口、菜单完成判断和继续导航仍由确定性规则负责。

人工边界不再直接触发挂断，而是先发出带 `deadline_at` 的 `boundary_pending` 事件。裁决窗口的兜底挂断由后端负责：后端收到 `boundary_pending` 后向 FreeSWITCH 注册到点 `uuid_kill`，到点仍未收到 `boundary_cancelled` 就执行挂断；中继进程崩溃或事件通道断开都不会让通话悬停。

冲突裁决规则是：

- 规则准备发送已确认的目标键，模型判定为 `human_or_unknown` 时，不发键并安全挂断。
- 规则准备发送已确认的目标键，模型判定为 `automated_notice` 时，本次不按键也不挂断，延长监听一次（固定 10 秒，每通最多一次）；延长结束仍不是菜单时按 `unknown_boundary` 安全挂断。
- 规则准备因人工边界挂断，模型判定为 `ivr_menu` 或 `automated_notice` 时，撤销该挂断并继续监听。
- 规则准备因未知边界挂断，若已有 `ivr_menu` 裁决，则撤销该挂断并继续监听。
- 模型不能选择按键、不能发送 DTMF、不能主动推进导航。

## Considered Options

- **只观察**：模型完全不影响通话，最安全，但无法纠正“规则把人工边界当成菜单”的误判。
- **单向否决**：模型只能要求挂断，无法阻止规则误判非工作时间提示为人工边界并挂断，不能解决已烧掉预算的主要故障。
- **受限咨询**：模型可在规则不决时从已出现的按键中选择目标键，能提升按键命中率，但存在幻觉发错键的风险。
- **共同决策**：每个 ASR 片段都让模型投票，延迟、成本和随机性不可控，不采用。

## Consequences

- 影子判断由独立环境开关 `SHADOW_JUDGMENT_ENABLED` 控制，默认关闭。开关关闭时行为与 ADR 0030 完全一致，人工边界立即挂断，不产生裁决窗口。
- 人工边界挂断在启用影子判断后可能晚一个短暂裁决窗口；超时后仍按规则原判挂断。
- 影子判断只由关键动作触发：规则识别到目标键时提前启动，规则检测到人工边界时启动。动作点消费已有结果，不额外阻塞确定性流程。
- 影子调用设置 1.5 秒硬超时；失败、超时或无法解析的输出一律视为未裁决，不改变规则原动作。失败分类记录为 `timeout`、`rate_limit`、`http_error`、`invalid_json`、`invalid_classification`、`low_confidence`，执行语义统一为“未裁决”。
- 置信度门槛非对称：规则想继续、模型要求挂断时门槛为 0.6；规则想挂断、模型要撤销时门槛为 0.9。
- 模型输入只包含带 partial/final 标记的滚动 ASR 上下文，不包含菜单树、历史模型结论或规则内部状态。滚动文本原样发送给 DeepSeek，不做脱敏；规则挂断或模型判定 `human_or_unknown` 后，立即停止该通话后续的影子调用。
- 影子模型不得阻塞确定性决策链；模型延迟、限流和失败时一律按规则原动作执行。
- 模型只能在规则已识别的动作之间否决，不能创造新动作或选择新按键。
- 每次影子判断的输入、输出、延迟和最终动作以 JSONL 追加写入 `SHADOW_JUDGMENT_AUDIT_DIR`，并通过 `shadow_verdict` 事件进入实时事件流，供离线评估。
- 启用真实通话前必须先用既有历史录音走真实腾讯实时 ASR 做离线回放，按决策点标注校准。校准标准为：撤销挂断方向零误报，要求挂断方向至多 1 次误报，三类分类总体准确率不低于 0.9。
- 影子裁决不写入节点或菜单树，只进审计与事件流。
