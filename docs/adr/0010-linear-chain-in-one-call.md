# 同一次探索呼叫连续经过已知线性链路

隐私同意、语言选择等节点通常是一条只有一个正确路径的线性导航链。为每个节点单独发起外呼会重复经过相同前缀并放大呼叫量。项目决定：同一次探索呼叫可以连续执行多个已知的线性节点，只有到达分叉点后为探索不同兄弟分支才发起新的探索呼叫。每通分支探索只发送当前目标路径；根节点只监听；同一通电话不探索兄弟分支。呼叫预算按真实外呼次数计算，不按通话内的 DTMF 步骤或节点数量计算。

## Consequences

- 发现相同链路时显著减少重复外呼和重复隐私确认。
- 探索流程必须能够表示“当前通话已到达哪个线性位置”和“下一个分叉点在哪里”。
- 线性链路的按键必须在单次通话内按顺序发送；固定时间序列是否足以可靠导航，需要单独定义。
- 兄弟分支仍需要新的探索呼叫，因此不能把整棵 IVR 当作一次通话完成。
- 根节点呼叫不发送 DTMF；分支呼叫发送目标路径后，遇到新的多选项菜单即结束并由后续通话分别探索。
